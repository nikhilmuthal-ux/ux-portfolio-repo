Overview

What is BW5

TIBCO makes integration software. It helps the apps and systems inside a large business talk to each other and share data in real time.

TIBCO BusinessWorks 5, or BW5, is the core tool that makes this happen. Instead of heavy coding, developers visually design workflows that connect databases, websites and applications.

I designed how BW5 apps live in Control Plane, from start to end.

The aim

BW5 should feel native in Control Plane. Learn one page, and every other already makes sense.

02

The challenge

Many flows, and screens that had grown apart.

  1. Pages organised differently

    Capability, domain and app pages each had their own layout, so the same task looked different on each.

  2. Mixed components

    Input sizes, footer buttons on the left, toggle size controls and old tables sat next to the new design system.

  3. Long flows with weak endings

    Build, deploy and provision ran across many screens and ended without a clear success or failure state.

  4. Critical moments with little care

    Making an endpoint public, rolling back a release and accepting the agreement had no real treatment.

Problem statement

How might we give BW5 teams one clear way to build, deploy and run their apps in Control Plane?

P1Same structure everywhere

Same sections, same order, same actions.

P2Keep the product's words

App Builds and Available Supplements stay exactly as users know them.

P3One modal, many flows

Same size, header, steps and footer.

P4Color means status

Running green, Critical amber, Stopped red.

06

Key decisions

Three changes that shaped the work.

D01

Top tabs became a left navigation

Tabs could not hold a second level.

  1. 01Groups open in place, one click to any page.
  2. 02Content gets the full width, run controls stay in the header.
  3. 03Every app page uses it.

Trade-offThe left navigation takes width, so the product navigation collapses to icons inside an app.

D02

Upgrade moved from a full page into a guided wizard

A full page for one choice, with no review step.

  1. 01Stays on the capability page, in the standard modal.
  2. 02Latest and Current tagged, older versions one click away.
  3. 03A review step before anything is provisioned.

Trade-offOne more step to reach the result, kept because provisioning is hard to undo.

D03

Provisioning moved into the same modal pattern

A separate full page, a different look from every other flow.

Before the original flow, 3 full pages

After one modal, 4 states

Real screens from the design file. Product and people names are blurred. BW5 uses the same flow, where adapters are called plugins.

  1. 01Runtime picked once, in a context box at the top.
  2. 02Plugins and custom upload as two clear tabs.
  3. 03A success and a failure screen, each with a next step.

Trade-offA fixed modal size means long plugin lists scroll inside the body instead of growing the page.

What I learned

Keeping long product labels exactly as users know them, like Available TIBCO Software & Plugins On This Data Plane, meant the layout had to make room for the words, not the other way round.
